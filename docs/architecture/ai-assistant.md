# Invekta AI

Existing message composer (`api/ai.py`, `AiAssistant.tsx`) now selects a single Groq chat-completions provider when explicitly enabled. Disabled mode preserves local templates and labels their limitations. An enabled provider without its separate `CRM_GROQ_API_KEY` returns 503, with no fallback or network request. Legacy OpenAI credentials are never reused. No new packages or lockfile changes are required. See README for exact environment setup, Free-plan caveat and owner-controlled Manus publication.

`ai_provider.py` posts only to `https://api.groq.com/openai/v1/chat/completions`, sends JSON instructions and validates nonempty bounded subject/body with extra fields forbidden. Truncation/refusal/invalid JSON is rejected. No tools, email sending, browsing, automatic retries or paid-provider fallback. The default Groq-hosted `openai/gpt-oss-120b` is listed in Groq's current Free limits (checked 2026-10-15); model availability and billing plan remain account settings. Client output is plain editable text, never executable HTML.

Context contains the selected visible company, optional matching contact/opportunity, explicit user input and current brand knowledge. It excludes other clients, other brands' knowledge and sales-document binaries. Selected contact email is used only as recipient, not sent automatically; freeform input/signatures may contain personal data. Generation occurs only on explicit submit with a disclosure next to the form. No retention guarantees are implied for the provider.

Author/session/active membership/company visibility are checked before calling and again before returning content. The 20-attempt/15-minute per-user budget remains. The user-row lock reserves budget before releasing the transaction for the network call. Provider failures consume an attempt; missing configuration does not. Revoked access prevents returning generated content. `POST /ai/generate` returns only subject/body/recipient/model; it never creates or updates an AiDraft. Attempts contain actor/time, never user prompts or output text. The browser keeps composition and generated edits in React state only, with no localStorage/sessionStorage/IndexedDB, history list or save button. Navigation/refresh starts empty. Existing database and browser drafts are left untouched; the legacy authenticated private GET remains read-only for compatibility, while old POST/PATCH return 410 after access checks. No schema change is needed for this removal.

`brand_knowledge.json` bundles short sourced public summaries from owner-supplied official websites, with source URLs/date. It is a starting knowledge base, not a complete catalog or live retrieval system. `brand_knowledge.py` uses bundled content only until an administrator saves an override; an explicit empty override remains empty. GET/startup performs no seed or writes. `api/ai_knowledge.py` lets enabled members read their brand knowledge and only brand admins/platform admins with membership update it. Payloads are bounded to 12,000 characters (fits MySQL TEXT with utf8mb4), versioned with row locks and conflict checks. Row-creation races return 409. Sources are facts rather than trusted instructions; model accuracy is still subject to human review.

Migration `c9d7a4e8f201` over `b8a6c2d1e409` adds a single table using portable types and foreign keys, without modifying existing records. Readiness checks the table publicly without needing AI configuration. Review/backup before applying on managed storage; all implementation-time DB work is restricted to isolated local PostgreSQL `_test`. Docker still bundles `/app/shared` and `/src/shared`, uses one port and existing locked dependencies.

Regression tests mock Groq transport and cover JSON protocol, rate/time/auth/provider errors, legacy-key isolation, brand scoping, shared knowledge permissions, stale writes and default/empty overrides. Browser tests exercise the actual FastAPI/PostgreSQL access with a mocked upstream response and assert no message persistence. A real Groq call/Serbian output quality must be confirmed after the owner's server key is configured. Never use production customer data for that initial check.
